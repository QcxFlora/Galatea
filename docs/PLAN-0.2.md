## 1. 设计语言：瑞士国际主义 × 少色彩

> 修订：放弃"方舟多色彩职业色"，改为 **Swiss Style / International Typographic Style** 为骨架，
> 只借用方舟的**工业细线**与《来自星尘》的**深空留白**，配色收敛到**黑 / 白 / 灰阶 + 一个强调色**。

### 1.1 从哪儿来（不是猜的）

| 来源 | 借什么 |
|---|---|
| 瑞士国际主义（Müller-Brockmann / 苏黎世/巴塞尔学派） | 网格系统、非对称布局、无衬线单一字族、大量负空间、左对齐齐头不齐尾、无装饰 |
| 明日方舟官网实测 | 1px 30% 白细线、6rem 行高、字距 1–2px、Oswald 窄体标题的做法 |
| 《来自星尘》 | 深空底色、同心轨道、点阵、留白比例、克制的慢动效 |

### 1.2 色板：一个彩色都不多给

| Token | 值 | 用途 |
|---|---|---|
| `ink` | `#0A0A0A` | 全局底 |
| `paper` | `#FFFFFF` | 纸面（属性面板、对话框、弹层）——瑞士风格必须有白版面 |
| `gray.900` | `#141414` | 浮层 |
| `gray.800` | `#1F1F1F` | 控件底 |
| `gray.700` | `#2A2A2A` | 细线（深底上） |
| `gray.500` | `#8A8A8A` | 次要文字 |
| `gray.300` | `#C4C4C4` | 已完成状态、次级标签 |
| `gray.100` | `#E8E8E8` | 主线文字、白面板上的分隔线 |
| **`accent`** | **`#E4032E`** | **全项目唯一彩色**：选中、当前、错误、脚本、进度 |

> 规则：屏幕上同时出现的彩色面积 **< 3%**。所有"类型区分"都不再靠颜色，
> 而靠**字号 / 字重 / 灰阶亮度 / 大写字母标签**（这正是瑞士风格的解法）。

### 1.3 节点类型：用灰阶亮度 + 字母标，不用彩虹

| 节点 | 灰阶 | 角标 |
|---|---|---|
| 台词 say | `#E8E8E8` 最亮（主线最重） | `SAY` |
| 选择 choice | `#C4C4C4` | `CHOICE` |
| 条件 branch | `#A0A0A0` | `BRANCH` |
| 变量 set | `#8A8A8A` | `SET` |
| 子图 call | `#7A7A7A` | `CALL` |
| 跳转 / 返回 | `#5A5A5A` | `JUMP` / `RET` |
| 结局 end | `#FFFFFF` + 2px 实线 | `END` |
| **脚本 script** | **`#E4032E`（唯一的红）** | `SCRIPT` |

> 红色只给「脚本」（外来代码）与「选中/错误」，一眼就能在图里找到自己的代码块。

### 1.4 字体：单一无衬线族 + 一座等宽数字

| 用途 | 方案 |
|---|---|
| 全部 UI | 系统无衬线（Roboto / HarmonyOS Sans / MiSans / Helvetica Neue），**不内嵌**（省 200KB+，瑞士骨架在网格不在字形） |
| 数据与代码 | 系统等宽 `monospace` + `font-feature-settings: "tnum"`（表格数字对齐） |
| 字重层级 | 只用 400 / 600 / 800 三档，禁止 500 这种暧昧值 |
| 字号阶梯 | 10 / 11 / 12 / 14 / 16 / 20 / 28 / 40 / 64（8px 基线栅格） |
| 字距 | 小标签 `+0.14em`（大写）、正文 `0`、大标题 `-0.02em` |
| 对齐 | **一律左对齐**，齐头不齐尾；数字右对齐 |
| 行高 | 正文 1.5、标签 1.2、列表行 40px（移动端不做 6rem 那种巨松） |

### 1.5 几何：零圆角、零阴影、只有细线

- **圆角全部归零**（`0px`），唯一例外：圆形状态点
- **不用阴影**，层级靠 1px 线与灰阶差
- 45° 切角保留一处即可：**卡片右上角切 8px**（来自方舟，但克制）
- 栅格：8px 基线，节点宽 240（30×8），间距 16/24/32/48
- 三栏比例：工具 56 / 画布 auto / 属性 320 = 严格 7 : 1 : 4 的模块

### 1.6 留白与网格

- 画布四周保护带 48px；节点间最小 32px
- 面板内 padding 20px，分组间距 32px
- 背景：极淡 8px 点阵网格（`rgba(255,255,255,.04)`）+ 一组同心轨道（`rgba(255,255,255,.06)`，来自星尘）
- 所有元素**吸附 8px 网格**（拖动时自动 round 到 8 的倍数）——机械感、秩序感

### 1.7 动效：运动中的秩序

| 场景 | 手段 | 参数 |
|---|---|---|
| 按下反馈 | lilt 弹簧 `Interactive` | 0.14 / 1.0，幅度 ≤ 2px |
| 面板/页面转场 | `cubic-bezier(.2,0,0,1)` | 120 / 200 / 240ms |
| 列表进入 | 线性淡入 + 8px 上移 | 200ms，stagger 40ms |
| 折叠/展开 | 高度 + 透明度同驱动 | 240ms |
| 背景轨道 | 线性慢漂 | 12s 循环 |

> 瑞士风格的运动是「精确、短促、不花哨」：**取消弹跳**，只保留位移与淡入；
> lilt 弹簧只用于手指按下/松开的即时回馈（那一瞬间的物理感是人机手感，不是装饰）。

### 1.8 里程碑内的顺序

1. 先落 token（色板/字号/间距/圆角/线宽）→ 全站自动换装
2. 再重排横屏三栏（严格网格）
3. 最后调节点卡片（灰阶 + 字母标 + 8px 吸附）

## 3. 系统栏适配（3 按钮导航）

现状问题：底部 48dp 被系统导航栏覆盖，工具条按钮点不到。

方案：

1. **读取真实安全区**：`MediaQuery.of(context).viewPadding`（不是 `padding`，避免键盘弹出时抖动）
2. **所有贴边容器**统一走 `SafeArea(bottom: true, left: true, right: true)`，并在自绘布局里手动加
   `EdgeInsets.only(bottom: viewPadding.bottom, left: viewPadding.left, right: viewPadding.right)`
3. **Android 侧**：
   - `SystemChrome.setEnabledSystemUIMode(SystemUiMode.edgeToEdge)` + 透明状态栏
   - `android:windowSoftInputMode="adjustResize"`
   - 3 按钮导航栏高度按 `viewPadding.bottom`（典型 48dp）自动避让，不写死
4. **Web 侧**：`padding-bottom: env(safe-area-inset-bottom)`
5. **新增「安全区调试」开关**（⋯ 菜单）：把 `viewPadding` 用青蓝色半透明条画出来，方便你在真机上核对
6. CI 加一条 `flutter analyze` + 单元测试验证 `SafeAreaInsets` 计算函数（纯函数，可测）

## 4. 脚本方块

`script` 节点从"小卡片"升级为**代码方块**：

```
┌───────────────────────────┐
│⚙ SCRIPT          scripts/intro.rs │  ← 右上切角
│ entry: opening()          │
│───────────────────────────│
│ 1  fn opening() {         │  ← 等宽字体，只读预览 2 行
│ 2    set("看过开场", true) │
│───────────────────────────│
│  emit: bgm · cameraY · beat│  ← emit 通道标签
│  ⏱ 0.8s                   │
└───────────────────────────┘
       ○ enter    ○ next
```

- 双击方块 → 全屏只读代码（行号 + 关键字高亮）
- 端口：`enter`（可选，被 call 时用）、`next`
- emit 通道作为**小标签**列出，播放器按通道消费
- 校验：`src` 文件不存在 / `entry` 函数不存在 → lint 报错（Rust 侧已能检测）

## 5. 支线折叠

```json
"groups": [
  { "id": "g1", "title": "雨夜相遇", "color": "#19D1FF",
    "collapsed": false, "nodes": ["n1","n2","n3"], "x": 0, "y": 0, "w": 640, "h": 480 }
]
```

- **框选**：长按空白拖框 → 选中多个节点 → 「折叠成支线」
- 折叠后：显示一个 `▣ 雨夜相遇 · 3 节点 · 2/3 完成` 的块，块间连线保留（连到块边框）
- 展开：点击块上的 `▸`
- 嵌套：**只支持一层**（v0.2 不做嵌套，避免布局爆炸）
- 删除块 ≠ 删除节点；块只是视图

## 6. 完成状态

```json
{ "id": "n3", "status": "todo" }
```

| 状态 | 显示 | 含义 |
|---|---|---|
| `todo`（默认） | 左上角空心小方块 `□` 灰 | 还没写完 / 占位 |
| `wip` | 半填充 `◧` 黄 | 收尾中（有内容但要打磨） |
| `done` | 实心 `■` + 勾 青 | 已完成、可交付 |

- 新建节点默认 `todo`
- 顶部/底部过滤条：`全部 / 未完成 / 收尾 / 已完成`
- 进度环：`已完成 / 总数`（方舟式细环 + 中心数字）
- 框选批量改状态
- lint 汇总：`还有 12 个节点未完成`（warning 级，不阻塞导出）
- 导出时可选「只导出已完成节点」（做 demo 切片用）

## 7. MCP 接口

新增二进制 `galatea-mcp`：**stdio JSON-RPC 2.0**，实现 MCP 规范（`initialize` / `tools/list` / `tools/call`），零依赖（与引擎同风格）。

| 工具 | 作用 |
|---|---|
| `story_open` | 打开/新建剧本文件 |
| `story_save` | 保存（自动 fmt） |
| `story_graph` | 读全图：节点（含 status）、连线、分组、统计 |
| `node_add` | 加节点（类型 / 位置 / 字段 / 自动连线到选中节点） |
| `node_update` | 改任意字段（text / speaker / cond / effects…） |
| `node_delete` | 删节点（自动剪线） |
| `node_connect` | 连一条边（from + port + to） |
| `node_disconnect` | 断一条边 |
| `node_set_status` | 批量设 todo/wip/done |
| `group_create` / `group_fold` | 建/折叠支线 |
| `story_lint` | 返回问题列表（error/warning/info） |
| `story_simulate` | 从入口跑到某节点，给定选择序列，返回事件流 |
| `script_run` | 跑脚本函数（含 `--sample` 曲线） |

**AI 的典型工作流**（这就是"让 AI 接入"的价值）：

```
story_graph → 看到 40 个节点、12 个 todo
  → node_add 加 5 个台词节点
  → node_connect 串起来
  → story_lint 自检
  → story_simulate 跑通主线
  → node_set_status 标 done
```

测试：`tests/mcp_*.rs`，用 JSON 行喂 stdin，断言 stdout JSON；CI 里跑。

## 11. 方块体系扩充（v0.2 增补）

> 由「剧情图」升级为「**作品图**」：不只是台词，角色、立绘、背景也变成图上的方块。

### 11.1 新增方块类型

| 类型 | 角标 | 内容 | 端口 |
|---|---|---|---|
| `character` | `CHAR` | 角色卡：key / 显示名 / 主题色 / 立绘集合 | `next`（可选） |
| `portrait` | `ART` | 立绘：属于哪个角色 / 资源路径 / 表情名 | `next`（可选） |
| `background` | `BG` | 背景：资源路径 / 场景名 | `next`（可选） |
| `say`（已有） | `SAY` | 台词，可**连到**角色与立绘方块表示"这句用这套素材" | `next` |

台词方块多两个**资源引用端口**：`cast`（连角色）与 `art`（连立绘）。这样"这句台词是谁说的、用哪张图"在图上一眼可见，而不是藏在 JSON 字段里。

### 11.2 合并显示（Collapse）

选中多个方块 →「合并成一块」→ 生成一个 `group`：

```
┌─────────────────────────────┐
│ ▣ 雨夜相遇      3 节点 · 2/3 │   ← 合并后的块（可展开）
└─────────────────────────────┘
```

- `group = { id, title, collapsed, nodeIds, color? }`
- `collapsed=true`：组内方块不单独渲染，只画这一个合并块；组内连线隐藏，跨组连线接到块边框
- `collapsed=false`：正常渲染内部方块，并画一个虚线框标注归属
- **单个组独立开关**：每个组合并状态存在自己的 `collapsed` 上

### 11.3 分组与独立开关

- 合并块可以再**分组**（`group.parent`），形成「组 → 合并块」的层级
- 界面上是一个**分组列表**（侧边抽屉）：
  ```
  ▸ 第一幕 · 雨夜            [合并 ✓]
     ▸ 雨夜相遇（3 节点）     [合并 ✓]
     ▸ 店内对话（5 节点）     [合并 ✗]
  ▸ 第二幕 · 离别            [合并 ✗]
  ```
- 每个条目右侧一个开关，**只影响它自己**；组开关只切换"这一组是否折叠成一块"，不连带子项（子项各自保持）
- 点击条目 = 在画布上定位并高亮

### 11.4 专门的列表

新增「方块列表」面板（竖屏从底部上滑 / 横屏从右侧滑入）：

| 列 | 内容 |
|---|---|
| 类型 | 小号大写角标 `SAY / CHAR / ART / BG / CHOICE …` |
| 标题 | 角色名 / 台词首句 / 组名 |
| 完成度 | `□ / ◧ / ■` |
| 归属 | 所在组 |
| 操作 | 定位 / 合并开关 / 改状态 |

支持：按类型筛选、按完成度筛选、搜索、批量改状态。

### 11.5 实现顺序

1. 数据模型（Rust/Dart/JS 三端）：`groups` + 三种资源方块 + 台词资源端口
2. 画布：渲染组（合并块 + 虚线框 + 跨组连线）
3. 交互：多选模式 → 合并/解散
4. 列表面板 + 分组开关
5. lint：组内节点不存在 / 节点重复归属 / 资源方块未连线

## 10. 风险

| 风险 | 应对 |
|---|---|
| Bender 字体授权不明 | 换 JetBrains Mono（OFL） |
| 思源黑体体积大（10MB+） | 不内嵌中文，走系统字体 fallback |
| 横屏小屏画布窄 | 属性面板可折叠 + 画布全览快捷键 |
| 折叠组让连线变乱 | v0.2 只做单层折叠，块间连线走边框锚点 |
| 大改容易一次崩 | 每里程碑独立 commit，CI 必须绿才进下一个 |
